# 故障处理：常见情况对照表



> 从 SKILL.md 挪出来的细节。遇到这些情况先查这里，别自己发明流程。



## 常见情况



| 情况 | 怎么办 |

|---|---|

| 没传课测答案 | 能跑，话术降级成「请把错题号发我」。先问一张卡：`这讲有答案吗` → `有，我发你` / `没有，按卷面来` |

| 有人缺考 | `"分数": null, "缺考": true`，不参与平均分 |

| 分数是 36.5 | 照实填，脚本支持小数 |

| 重名 | 名单自动加 `(2)` 区分，告诉老师 |

| 照片是 HEIC（iPhone 原图） | `python <SKILL>/scripts/转jpg.py --目录 "照片/<班级>/<课次>"`，Mac 用系统 sips，Win 需 pillow-heif |

| 老师说「上次那个班再来一次」 | 先 `新建班级.py --列出` 看有哪些班，别新建 |

| 老师给的是旧版群发表（没有文本列） | 让老师从教师精灵重新导出 |

### 它自己会拦住你（不用你判断）



| 日志长这样 | 意思 | 你要做什么 |

|---|---|---|

| `[错] 这份名单里一个分数都没有 —— 还没有登分` | 没跑 `ingest.py` 就想生成 | **先登分**。这时它什么都没写，成绩历史没被污染 |

| `[停] 第 N 步没法做：上面那条 [错] 就是原因` | 前置条件没满足（没登分／名单为空／参数冲突） | 把上面的补上重跑。**不是程序坏了，别叫老师截图** |

| `[跳过] … 没有本讲题库` | 第 2 项没做 | 想给缺考孩子补材料，就先把题库写进 `题目/<班级>_<课次>/题库.json` |

| `[注意] … 有部分失败——群发和归档照常往下做` | 个别人没出报告/巩固单 | 群发里会缺这几个人，先看那几行 `✗` 再决定发不发 |

| `[中断] … 返回码 N` | 真的出错了 | 这才需要截图给技术同学 |



**退出码约定**：`0` 全好；`1` 跑完了但有缺口；`2` 前置条件没满足（人话能说清）；`3` 没题库跳过。



> **必须先跑过第 4 节的 `ingest.py`。** 它会写 `大题扣分.json`，

> 报告里「各模块得分率」的分母和分子都从这个文件来。

> 没有它，模块得分只能按错题号 × 每题分值估——卷面印「每题 2 分」但老师实际按 1 分扣时，

> 估出来的模块失分加起来会大于总分，表里数字对不上。



> **没勾第 4 项（巩固练习）时，话术里那句「我整理了一份小任务（附件）」就落空了。**

> 这时要么把 4 补上，要么提前告诉老师：「这讲话术里提了练习，但我们没生成，

> 需要的话我补一份，不需要就照着发，家长不会细究。」



## 跑得慢



先看日志最后那句 `（x.xs）`：那是一个步骤的真实耗时。对号入座：



| 现象 | 原因 | 怎么办 |

|---|---|---|

| 40 人整条链超过 20 秒 | 机器只有 2 核，或者并行没生效 | 正常范围是 7-12 秒。加 `--串行` 反而更稳 |

| 「诊断报告 + 巩固练习」一步就 10 秒以上 | 人数多、又没走并行 | 看日志有没有 `（N 个进程并行，M 人）`；没有就是人数不到 20，本来就该串行 |

| 「整理成标准目录」卡十几秒 | 上一次的产物堆在目录里，正在清理 | 正常。清理是一次性成本，下一讲会快 |

| 每一步都要等 1-2 秒才有输出 | 在加载图片/文档库 | 整条链只加载一次，不是每步都等 |

| 几分钟都不动 | 真的卡死了（多半是杀毒软件在扫生成的图片） | 等一轮；还不行就关掉杀毒软件的「实时扫描」再重跑 |



**不要把「慢」当成「坏了」。** 判断标准只有一条：日志还在往下走 （有人在打印 `[3/5]`、

`[12/40]`），就说明在干活。
